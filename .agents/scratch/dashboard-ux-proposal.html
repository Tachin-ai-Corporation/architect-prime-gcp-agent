Admin Dashboard
Redesign.

No sidebars. Every screen is its own page. Breadcrumbs connect everything. Big cards navigate. Projects organize work. The mission tree breathes in real time.

00 · foundation
Design principles.

Every screen is its own page.

No sidebars, no split panes. Each screen fills the viewport. Content breathes.

Breadcrumbs are the spine.

Persistent top bar on every screen. Click any segment to jump back. Always know where you are.

Cards navigate forward.

Hub screens present children as big tappable cards. Deeper screens are one click away.

Two interactions max.

Deploy, hire, fire, swap models, create projects. One to initiate, one to confirm.

Calm over busy.

Default state is quiet. Nothing pulses unless something needs attention.

Live, not stale.

Firestore listeners power every screen. Progress bars move. Status changes propagate without refresh.

01 · information architecture
The nesting hierarchy.

Every screen sits at one of five nesting levels. Breadcrumbs follow this tree exactly. Cards on each screen point to its children.

◆ Home — all Primes, global actions
├─ Prime "{name}" — one factory's hub
├─ Chat — operator ↔ Prime conversation
├─ Projects — organized groupings of work
└─ Project "{name}" — one project's missions, agents, progress
├─ Fleet — agent roster under this Prime
└─ Agent "{name}" — one agent's hub
├─ Chat — direct DM with this agent
├─ Work — this agent's live task timeline
├─ Brain — 6-slot LLM picker
├─ Skills — installed kits + library
└─ Settings — SOUL, identity, responsibilities, fire
├─ Work — fleet-wide mission tree (real-time, all projects)
├─ Models — LLM library + Vertex AI scan
└─ Settings — Prime-level config + defaults
├─ + Deploy Prime
└─ Dashboard Settings — global config, DWD, domain, skill kits
Projects are an organizing layer for work. They sit between Prime and the fleet-wide Work tree. A Project groups related Missions. Agents work across multiple Projects. The fleet-wide Work screen shows all Missions across all Projects, with a filter to scope by Project.

Visual language for task states. Every node in the tree uses the same visual vocabulary:
✓ Mint = complete. ● Aqua + pulse = in progress (with progress bar + elapsed time). ⚡ Amber = needs input (with countdown timer). ○ Gray = pending. Progress bars appear inline on active tasks and checkpoints. Agent chips on every node show who's responsible, with a pulsing dot when they're actively executing.
Agent Focus strip. A horizontal bar above the tree shows every agent in the fleet with their current state — what they're working on right now, or how long since their last task. Working agents have a pulsing mint chip. Idle agents show last-active time. This gives the operator one-glance fleet awareness without drilling into each agent.

  • Resp. cardsEach responsibility shows name, owning agent, cron expression, next fire time, total run count, and a 7-day heatmap (green pips = days it ran). Clicking a card expands to show the last 5 runs with status and duration.
  • Click-in detailExpanding a responsibility reveals: last 5 run timestamps, pass/fail status of each run, the Mission envelope it most recently created, and a link to the agent's SOUL for the responsibility definition.
  • Agent SettingsResponsibilities can also be managed from the Agent Settings screen — the same scheduler but scoped to one agent. Changes hot-reload to the VM.

appendix
How screens connect.
  • ForwardHub screens show children as big nav cards. Click a card → land on that screen.
  • BackwardBreadcrumb segments are clickable. Click any ancestor → jump back.
  • LateralOne breadcrumb back to the parent hub, one card forward to a sibling. Two clicks max.
  • Cross-linkProject detail → click mission → opens fleet Work tree at that mission. Agent timeline task → shows project tag → click to open Project detail. Work tree agent chip → click to open Agent hub.
  • Global"Home" always in breadcrumb. Bell badge always in top bar. Two clicks from the top, anywhere.
  • DeeplinksEvery screen has a unique URL. Bookmarkable. Shareable. Breadcrumb auto-populates from the URL path.
