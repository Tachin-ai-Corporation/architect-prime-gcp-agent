### Dispatch Pattern
- **Brain v3 state machine (`agent-brain.mjs`)**: Manages deterministic, envelope-based coordination as a continuous service.
- **Cortex JSON Decide Loop**: Cortex classifies inputs and makes structured decisions (`action: "classify"|"decide"|"short_circuit"|"dispatch"|"synthesize"`). 10-case response normalizer infers actions from fields present (e.g., `intent:"synthesize"` → synthesize, `blocker` → blocked, `result` → synthesize fallback).
- **Schema-alias normalization (`corekit/lib/vertex-text.mjs` `normalizeDecision`)**: cortex reliably echoes the mode marker (`"action":"classify"`) and drifts on the real decision's field name — historically fixed for `move`→`action`, `attach_to_mission`→`attach_to`, `continue_to`→`continue_mission`; as of v2026.07.12.4.0 also `type`/bare `action`→`classification` for the classify schema (guarded against aliasing the literal `"classify"` echo itself). `enforceSchemaFn` parses+normalizes the raw response exactly once and reuses that object for both the deterministic validate and the fast-exit — do not reintroduce a second fresh `parseJsonResponse(raw)` there, or an alias applied to the first parse silently won't reach the second. The classify fast-exit checks `classification` only; `action` is never a legitimate classify field.
- **R/M/C/T Hierarchy**: Work is managed as nested envelopes of Responsibilities (cron scheduled, individually toggleable), Missions, Checkpoints, and Tasks.
- **Sub-agent Dispatch**: Sub-agents are invoked dynamically by Cortex to execute planned steps.

### Outcome Integrity
Contract-driven guarantees that dispatch and completion produce verifiable results:
- **smartTruncate**: Content truncation follows a field-priority contract (`result` → `summary` → `notes`), never silently drops outcome data.
- **Mission record persistence**: `completeEnvelope` Step 3a writes a durable mission record to Firestore before marking the envelope complete.
- **Delegation trailer grammar**: Delegation dispatches append a machine-parseable trailer (envelope ref, expected output, return address) so the receiving agent can satisfy the contract.
- **Delegation validation gates (v2026.07.12)**: `handleDelegate` validates BEFORE creating envelopes — email shape (`normalizeTargetEmail` strips trailing punctuation the intercept regex captures), self-delegation, fleet-registry online lookup, and project-has-GChat-space (delegations deliver only through shared project spaces). Rejections return actionable `[SYSTEM]` feedback naming valid agents/projects. The delegation lives under a Checkpoint (M→C→T per C-15) and its T carries `source_meta.delivery_envelope_id`; the mouth retries failed deliveries with persisted exponential backoff (`contracts.delivery`, terminal `delivery_status='failed'` at max_attempts) and `checkWaitingEnvelopes` fast-fails the waiting T off that terminal status instead of waiting out the 4h delegation timeout.
- **Prime fleet-ops skills are prime-scoped (v2026.07.12.6.0)**: mirror of the fleet-only delegation scoping. `fleet-introspect` (`roles:["prime"]`, script `fleet-work-read`) is Prime's read-only OBSERVE capability — reads any fleet agent's missions/checkpoint-task trees from the shared root `work/` collection with the metadata token, no SSH. Prime's OPERATE path (shell for test/upgrade/remediate) works via `gcloud compute ssh --tunnel-through-iap`; the enabling grant is `roles/iap.tunnelResourceAccessor` on the Prime SA (the ONLY thing missing — compute.admin already covers instance access), codified idempotently in `fleet-deploy`. When reading large Firestore payloads in a shell tool, stream to a temp file and pass the PATH — never the payload as argv (the `work-log-read` "Argument list too long" bug).
- **Delegation is fleet-only + project-scoped (v2026.07.12.3.0)**: Primes never delegate — Prime cortex SOUL mandates direct fleet operation (SSH, work-log reads, fleet-verify/fleet-upgrade). Skills can declare `roles` in skill.json; `buildSkillIndex` filters by the agent role from `corekit/STATE.json` (stale skill dirs can't resurface a role-excluded skill). The delegate action, checkpoint_plan intercept, executor delegation steps (`delegationEnabled` dep), and process-engine all gate on the delegation skill being indexed; cortex prompt surfaces omit `delegate` when unavailable. Delegation additionally requires the mission to name a registered project (gate 0.5) with a GChat space.
- **Completion verification**: `synthesize` verifies that every dispatched checkpoint has a recorded outcome before composing the final response.
- **GOAL STATE + goal_check**: Prefrontal plans include an explicit `GOAL STATE` block; cortex runs a `goal_check` pass before synthesize to confirm the goal was met.
- **Organs own the HOW, skills own the tools (v2026.07.19)**: Prefrontal decomposes by *outcome/ownership/dependency*, never tool-step, and never names commands/API ops — it sees only the skill catalog (`formatSkillCatalog`), not the command surface, so naming a nonexistent `batch_update` step was the archetypal failure. Motor owns the full tool sequence *within* a Task (reads the governing SKILL.md, composes its verbs, iterates); a Task making many tool calls is normal, and Motor fails only when the outcome needs a cross-envelope split (different specialty / approval gate / real phase dependency), which the daemon re-decomposes — Motor mints no envelopes (C-17). SOUL/SOUL_APPEND files carry operating character + how-to-find-skills only, **zero tool syntax** (B-16/B-17); per-skill procedure lives in SKILL.md. `checkpoint_plan` re-plan nudge forbids finer decomposition; `checkpoint-executor` no-verdict paths are now fail-closed (re-verify once, then FAIL — not needs_review-and-pass); missing `accept_criteria` falls back to an outcome-framed default.

## Memory System (Three-Layer Lifecycle)
- **Working Memory** (`MEMORY.md`): Agent RAM — accumulates during sessions, pruned nightly to <2,000 chars
- **Core Memory** (Firestore `core_memory` collection): Long-term durable facts. Actively pruned via `core-memory-retire`
  - Scripts: `core-memory-read` (supports `--since` time-windowed queries), `core-memory-write`, `core-memory-retire`
- **Deep Truths** (`SOUL.md` `## Deep Truths` section): Behavioral firmware, max 10 items. Changes only during nightly consolidation (3+ sessions, 7+ day evidence)
  - Script: `update-deep-truths`
- **Dual-pass recall**: temporal-memory does targeted archive search (all time) + broad recent scan (30 days) + context fill
- **Nightly consolidation**: 10-step `r-memory-consolidation` responsibility (gather → triage → reconcile → retire → promote → prune → Deep Truths → report)

## Session Context Layer (2026-07-11)
The brain's context handling is measured, cached, bounded, and thread-true:
- `corekit/lib/prompt-blocks.mjs` — cache-tier block assembly (boot/mission/volatile); the gateway maps tiers to Anthropic cache_control breakpoints (1h TTL) and concatenates for Gemini.
- `corekit/lib/compaction.mjs` — checkpoint digests + token-triggered mission compaction ("roll at N%"): `compactMissionContext` in agent-brain.mjs splices a validated digest (verbatim criteria, binned claims) into `_accumulated_context` at `contracts.compaction` thresholds.
- `corekit/lib/thread-ledger.mjs` — (channel, thread)-keyed conversation cache written at intake claim / GChat backfill / delivery; read by classify fill-in and mouth voicing.
- `corekit/brain/context.mjs` — gateway session store (dark; `session.enabled`); cortex decide sessions send volatile-tier deltas; cerebellum structurally excluded (B-28).
Debugging: grep daemon logs for `[TELEMETRY] llm_usage` (cache splits), `compaction`, `session_open|session_miss`, `thread_turn_append`. Gateway `/status` lists live sessions.
