# infra/manifests/job-web-master.txt
# Web-Master specialty — single-handed ownership of a website vertical (design + content +
# code + Firebase deploy/config), layered on top of base + role-fleet.
# Installed by: infra/install.sh --role fleet --job web-master
#
# The web-master REUSES existing specialty skills rather than copying them in the repo: each reused
# skill is SOURCED from its owning specialty (single source of truth) but INSTALLED INTO THE
# WEB-MASTER NAMESPACE (corekit/specialties/web-master/skills/<skill>/). That dest is load-bearing:
# skill-setup provisions dependencies and builds the capability map ONLY for skills under
# corekit/specialties/${SPECIALTY}/skills/ (SPECIALTY=web-master here). Installing a reused skill
# under its owning-specialty dest instead (e.g. .../devops/skills/firebase) leaves it invisible to
# skill-setup, so its `requires` (e.g. firebase-tools, chrome) are never installed — a declared skill
# with a missing tool (C-9 phantom capability). Executables still go to bin/ (on PATH, not namespaced).
# Base skills (web-search, workspace-git, skill-introspect, memory-consolidate, workspace-drive tools)
# come from base.txt + role-fleet.txt — not re-listed here (same pattern as job-engineer.txt).
