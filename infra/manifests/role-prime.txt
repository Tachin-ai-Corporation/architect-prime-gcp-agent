# Workspace skills — DELIBERATELY ABSENT (C-1, B-17).
#
# Prime is a factory, not a doer. It previously installed SKILL.md + skill.json
# for workspace-drive/docs/sheets/slides/gmail/calendar and NONE of the ~60 tools
# those docs describe — not even ws-token, the auth helper every one of them needs.
# That is phantom capability: B-17 enforces skill use where a skill exists, so a
# prime cortex would discover workspace-docs, follow the SKILL.md, dispatch
# `docs-cat`, and get "command not found" — a guaranteed failure, not a guess.
#
# A Prime's power is general, not clerical: gcloud (gcp-admin), the shell
# (system-shell), scripting, git/GitHub, and web-search. Artifacts belong in git
# (C-24). Anything that needs Drive, Docs, Sheets, Slides, Gmail or Calendar is a
# fleet agent's job — hire one (fleet-hire) rather than growing a second pair of
# hands here. `gcloud storage` remains available via gcp-admin as an escape hatch.
#
# If a Prime ever genuinely needs a workspace surface, install the TOOLS with the
# doc — never the doc alone. validate-contracts Check 14c enforces exactly that.

# Repository authorship — DELIBERATELY ABSENT (C-34).
#
# `github-pr` and `git-ops` used to install here so Prime could open pull requests
# against the product repository. That made a deployment's learning arrive as
# cross-deployment code churn, with none of the separation the two improvement
# loops need: different cadence, different evidence, different approval, different
# rollback. And a deployed agent holding a repository push token means the
# Foundation boundary is a matter of prompt discipline rather than structure.
#
# Prime now improves this deployment through the Fleet Definition lifecycle
# (fleet-architecture, below) and escalates a genuine platform need as a Platform
# Finding. Repository authorship belongs to the Repo Maintainer environment, which
# is a different actor with different credentials.
